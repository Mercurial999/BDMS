# Documentation Archive

This folder contains historical plans and notes that are useful for understanding earlier decisions but are not active implementation instructions.

## Archive rules

- Current development direction is defined by [the development guide](../development-guide.md).
- Current feature evidence is recorded in [feature status](../feature-status.md).
- Proposed work and unresolved business decisions belong in [the backlog](../backlog.md).
- Technical structure belongs in the repository-root [architecture reference](../../ARCHITECTURE.md).
- Historical phase names, old branch instructions, and old status labels must not override current documents.
- Historical test records must retain their original scope and limitations. Do not describe a focused manual check as a full regression or release verification.

## Archived reference

- [Historical phase plans and decisions](phase-based-planning.md) — consolidated business direction, proposed future workflows, open decisions, and limited historical verification evidence from former phase-based planning documents.
- [Historical frontend planning notes](frontend-planning-notes.md) — superseded frontend plans, inventory visibility analysis, sales/report integration notes, and UI suggestions. Current visual conventions are in `../frontend-design-guidelines.md`.

New archive files should be added only when they preserve useful history that no longer belongs in an active guide. Do not archive duplicates merely to keep every obsolete file.
